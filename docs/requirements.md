# MDS AI判定 要件定義書

最終更新: 2026-04-03

---

## 1. プロジェクト概要

### 1.1 背景
従来の人事評価プロセスでは、社員が記入したミッション（業務目標）の質を上長が主観的に評価しており、評価者間のばらつきや透明性の欠如が課題となっていた。また、360度評価はExcelで管理されており、運用負荷が高く、集計に時間がかかっていた。

### 1.2 目的
AIによるミッション採点の自動化、360度評価のシステム化、ダッシュボードによるデータ可視化を通じて、人事評価の客観性・効率性・透明性を向上させる。

### 1.3 スコープ
- ミッション内容のAI採点（参考値としてのセルフチェック）
- 360度評価の運用管理（サイクル・割当・回答・結果）
- Google Sheets連携によるダッシュボード
- 社員・アカウントの管理機能

## 2. 機能要件

### 2.1 必須機能（MVP）

#### F-001: ユーザー認証
| 項目 | 内容 |
|------|------|
| 説明 | メール/パスワードによるログイン・ログアウト |
| 入力 | メールアドレス、パスワード |
| 出力 | JWT セッション Cookie の発行 |
| ビジネスルール | パスワードは6文字以上、bcryptでハッシュ化 |
| 実装状態 | ✅ 実装済み |

#### F-002: CarrierAuth（Google SSO連携）
| 項目 | 内容 |
|------|------|
| 説明 | Google OAuthを経由した外部認証基盤との連携 |
| 入力 | Googleアカウント |
| 出力 | CarrierAuth JWT セッション Cookie |
| ビジネスルール | 許可ドメインの検証、未登録ユーザーの自動作成 |
| 実装状態 | ✅ 実装済み |

#### F-003: 初回パスワード変更強制
| 項目 | 内容 |
|------|------|
| 説明 | `mustChangePassword` フラグが有効なユーザーにパスワード変更を強制 |
| ビジネスルール | 変更完了までダッシュボード等にアクセス不可 |
| 実装状態 | ✅ 実装済み |

#### F-004: ダッシュボード
| 項目 | 内容 |
|------|------|
| 説明 | Google Sheetsのミッションデータを集計表示 |
| 入力 | 期間・部署・氏名フィルター |
| 出力 | 統計カード、人物一覧テーブル、ミッション詳細展開 |
| データソース | Google Sheets API (`missions` シート) |
| 実装状態 | ✅ 実装済み |

#### F-005: セルフチェック（AI採点）
| 項目 | 内容 |
|------|------|
| 説明 | ミッション内容をAIが6次元で採点し、グレード・グレード給を算出 |
| 入力 | 役職、部門種別、ミッション（M1〜M5）×最大3つ、ウェイト |
| 出力 | 6次元スコア（各10点満点）、加重ポイント、総合ポイント、グレード、グレード給、AIコメント、レベルアップのヒント |
| ビジネスルール | ウェイト合計100%、M1は10文字以上、M2〜M5は30文字以上 |
| 採点基準 | `docs/scoring-criteria.md` 参照 |
| 実装状態 | ✅ 実装済み |

#### F-006: 360度評価 — 回答
| 項目 | 内容 |
|------|------|
| 説明 | 割り当てられた評価に対して各次元を1〜5で回答 |
| 入力 | 各評価次元のスコア（1-5）、コメント（任意） |
| 出力 | EvaluationResponse レコード作成、EvaluationAssignment ステータス更新 |
| ビジネスルール | サイクルが `open` の場合のみ回答可、提出後は変更不可 |
| 実装状態 | ✅ 実装済み |

#### F-007: 360度評価 — 結果閲覧
| 項目 | 内容 |
|------|------|
| 説明 | 自分の360度評価結果をレーダーチャート・カテゴリ別に閲覧 |
| 出力 | レーダーチャート、関係性別平均スコア、匿名コメント |
| ビジネスルール | サイクルが `closed` の場合のみ閲覧可、コメントは匿名化（シャッフル） |
| 実装状態 | ✅ 実装済み |

#### F-008: 360度評価サイクル管理（管理者）
| 項目 | 内容 |
|------|------|
| 説明 | 評価サイクルの作成・ステータス管理・評価者割当・結果閲覧 |
| ステータス遷移 | draft → open → closed |
| ビジネスルール | 削除は `draft` のみ、`open` で回答受付開始、`closed` で結果公開 |
| 実装状態 | ✅ 実装済み |

#### F-009: 評価者割当
| 項目 | 内容 |
|------|------|
| 説明 | 評価サイクルに対して評価者と被評価者の組み合わせを設定 |
| 方法 | ① 自動割当（上司・部下関係から自動生成）、② シートから読込（Google Sheets）、③ 手動指定（API経由） |
| ビジネスルール | 同一サイクル内で評価者-被評価者の重複不可（ユニーク制約） |
| 実装状態 | ✅ 実装済み |

#### F-010: 社員管理（管理者）
| 項目 | 内容 |
|------|------|
| 説明 | 社員マスタ（Employee）のCRUD |
| 入力 | 社員番号、氏名、部署、役職、等級、メール、上長 |
| ビジネスルール | 社員番号・メールはユニーク、役職はプリセットリストから選択 |
| 実装状態 | ✅ 実装済み |

#### F-011: アカウント管理（管理者）
| 項目 | 内容 |
|------|------|
| 説明 | ログインアカウント（User + Employee）のCRUD + パスワードリセット |
| 入力 | メール、パスワード（6文字以上）、ロール、社員情報 |
| ビジネスルール | 既存社員番号の再利用可（未リンクの Employee に紐付け）、パスワードリセット時は全セッション無効化 |
| 実装状態 | ✅ 実装済み |

#### F-012: アカウント一括作成（管理者）
| 項目 | 内容 |
|------|------|
| 説明 | CSVファイルによるアカウントの一括インポート |
| 入力 | CSVファイル（最大500件）、共通初期パスワード |

## 3. 非機能要件

### 3.1 パフォーマンス

| 項目 | 要件 |
|------|------|
| ページ初期表示 | 3秒以内（DBクエリ依存） |
| AI採点レスポンス | 10秒以内（Gemini API依存、1ミッションあたり） |
| 同時接続ユーザー | 50名程度 |

### 3.2 セキュリティ

| 項目 | 要件 |
|------|------|
| 認証 | JWT + サーバーサイドセッション（DB管理） |
| パスワード保管 | bcrypt（ソルトラウンド10） |
| Cookie | httpOnly, Secure（本番）, SameSite=Lax |
| 権限チェック | リクエスト境界 + レイアウト + API の3層 |
| SQL対策 | Prisma のパラメータ化クエリ |
| 機密情報 | `.env*` は Git 管理外、サーバーサイドのみ使用 |

### 3.3 可用性

| 項目 | 要件 |
|------|------|
| ホスティング | Vercel（自動スケーリング） |
| DB | マネージド PostgreSQL（Supabase 等） |
| 目標稼働率 | 99.5%（Vercel SLA に準拠） |

### 3.4 対応環境

| 項目 | 要件 |
|------|------|
| ブラウザ | Chrome, Edge, Safari（各最新版） |
| デバイス | PC（推奨）、タブレット・スマートフォン（レスポンシブ対応） |
| 言語 | 日本語のみ |

### 3.5 運用・保守

| 項目 | 要件 |
|------|------|
| デプロイ | Vercel（Git連携による自動デプロイ） |
| DB変更 | `prisma db push`（マイグレーションファイル未使用） |
| シードデータ | `npx prisma db seed` または `/api/setup` |
| ログ | Vercelのログ機能に依存 |
| バックアップ | DB側のバックアップ機能に依存 |

## 4. 制約事項

### 4.1 技術的制約
- Next.js 16 を使用しており、従来の `middleware.ts` ではなく `proxy.ts`（リクエスト境界）を使用する
- Google Sheets API はリアルタイム同期ではなく、毎回APIコールで取得する（キャッシュなし）
- AI採点はGemini APIの応答速度・レート制限に依存する
- `prisma migrate` ではなく `prisma db push` を使用しているため、マイグレーション履歴は管理されていない

### 4.2 ビジネス制約
- AI採点結果は参考値であり、最終的なグレード決定は人事部門が行う
- 360度評価の回答は提出後に変更不可（匿名性担保のため）
- 評価次元（項目）はGoogle Sheetsのマスタデータで定義され、アプリ内からは変更不可

## 5. 用語定義

| 用語 | 説明 |
|------|------|
| ミッション | 社員が設定する業務目標。M1〜M5の5項目で構成される |
| ウェイト | 各ミッションの重要度配分（%）。合計100% |
| グレード | AI採点結果に基づく等級（例: A1, L3, D5） |
| グレード給 | グレードに対応する給与加算額 |
| 役職グループ | 役職を5グループ（A/L/U/G/D）に分類したもの |
| 評価サイクル | 360度評価の実施単位。開始日〜終了日を持つ |
| 評価次元 | 360度評価の評価項目。役職グループごとに異なる場合がある |
| 関係性 | 評価者と被評価者の関係。上司/同僚/部下/本人の4種 |
| CarrierAuth | 社内共通のGoogle OAuth認証基盤 |
| 姉妹アプリ | 同じ認証基盤を共有する別システム（アカウント同期対象） |
